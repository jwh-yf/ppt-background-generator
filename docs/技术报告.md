> 本报告对应仓库当前状态：数据集 `data/dataset_v4`（生成器 1.5.0）、发布权重
> `train/runs/pptbg-lora-v5-nobokeh/checkpoint-1000`、网页应用 `app/`。
> 文中每个数字都能用第 11 节的命令重跑；评测原始数据在 `eval/results_v1/`。
> 第三版新增：六个可调项（配色/柔焦/磨砂强度/磨砂形状/元素密度/符号质感）、
> 元素池第二次扩容（高数 9 / 机械 8 / 哲学 9 件）、以及「模型笔触」的完整记录。

## 摘要

幻灯片背景图的难点不是「生成一张好看的图」，而是「生成一张**能把字放上去**的图」。
通用文生图模型的训练目标是细节丰富、对比强烈，与「大面积低对比、留出结构化空白」
这一需求正好相反；提示词写得再好也无法补上「哪里要放字」这条信息。

本作品把这个隐含需求显性化：定义**安全区**（适合压字的矩形区域），用局部亮度标准差
`safe_zone_std` 把「有多干净」变成可测量、可训练、可复核的指标，再用 LoRA 在自建的
600 张合成背景上教 SD 1.5 这个偏好；推理时用约束把不达标的地方压下去。

与第一版相比，第二版的变化集中在三处：**学科化**（分类从行业场景改为
高等数学 / 机械制图 / 人生哲学与科学方法论，并给每个学科建立一套挂在固定基准上的
符号系统）、**整套生成**（一次请求产出 8 页完整 PPT）、**权重换代**（v1 → v5）。

第三版把「可调」做成了产品的一部分：**六个可调项**让同一学科能出观感明显不同的背景
（每科 5 套配色、柔焦与磨砂两档模糊、磨砂形状方形/椭圆、元素密度三档、符号质感矢量/模型笔触），
学科元素池也从每科 5 件扩到 **9 / 8 / 9 件**，同 seed 下不再出现「十张看着一模一样」。

可信的效果：同一需求、同一 seed、同一条代码流水线下，加 LoRA 与不加相比，
安全区对比度 **6.43 对 16.05**（越低越干净），版式合规率 **100% 对 75%**。
工程上是 `http.server` + 纯 Python 实现，无 Gradio / Streamlit，依赖可从零复现。

## 1. 问题与场景价值

### 1.1 场景

做幻灯片时，背景图这件事有三个反复出现的痛点：

1. **找图耗时**：图库里翻十几分钟，最后随手拿一张，与汇报内容无关。
2. **图上压字读不清**：图很好看，但标题落在高对比区域，字要么糊，要么得加一块丑陋的色块。
3. **风格不统一**：一页一个来源，整份 PPT 像拼贴画。

### 1.2 为什么通用文生图模型解决不了第 2 条

通用文生图的训练目标是产出细节丰富、对比强烈的画面，而 PPT 背景需要的是
**大面积低对比、留出结构化空白**。两者目标相反。这不是「提示词写得不够好」能
解决的：模型没有「哪里要放字」这一信息，也没有为它优化的训练信号。

本作品把这件事变成一个**可度量、可学习、可约束**的量：定义「安全区」
（适合压字的矩形区域），用局部亮度标准差 `safe_zone_std` 度量它有多「干净」，
训练时让模型学习产出安全区干净的画面，推理后再用约束把不达标的地方压下去。

### 1.3 为什么改成学科分类

第一版的分类是行业场景（学术汇报、商业计划、公益项目…）。这类分类的问题是
**八个场景画出来是同一张抽象色场**——因为它们的差别只在色调，不在形体。
教师的意见很直接：应该按学科分，而且「每个背景要突出学科特色，不要纯色」。

学科的好处是**每个学科有公认的图形语言**：高数是坐标纸与函数曲线，机械制图是
图框、标题栏与尺寸标注，人生哲学是纸、墨与留白。这些形体是可判别的，看一眼就知道
是哪一科，而这正是行业场景给不了的东西。

代价也很明确：这些形体**必须由确定性代码画**，不能指望 512 分辨率的 LoRA 学会。
第 6 节用三组对照实验证明这一点。

## 2. 系统结构

### 2.1 分层

```
用户输入（中文主题 + 标题 + 学科 + 比例）
   │
   ▼
presets.compose_prompt      中文主题 → 英文提示词（词表映射 + 77 token 预算裁剪）
   │
   ▼
SD1.5 + LoRA 推理           512 短边生成 → 放大到目标尺寸（约 8–9 秒/张）
   │
   ▼
构图约束层                  layout_for_preset → 安全区矩形
   │                        → 学科符号（元素池抽签）
   │                        → 面板卡片 / 暗角 / 颗粒
   │                        → enforce_safe_zones（超阈值才动手，target_std = 26）
   ▼
保存 PNG/JPG + 安全区元数据（records）
   │
   ├─→ 网页实时预览（把用户自己的文字压上去看可读性）
   ├─→ 「重画这一张」（换 seed 只重画某个槽位，原地替换记录）
   └─→ pptx_exporter → .pptx（背景铺满 + 按安全区摆文本框，可直接改字）
```

### 2.2 一次生成整套 PPT

`POST /api/deck` 把「生成背景」和「排版」合并成一步：

| 步骤 | 做什么 | 为什么 |
|---|---|---|
| 1 | 只画 **3 张**底图（cover / content / end 取向） | 一整套 PPT 的视觉一致性要求底图少而统一；限功率状态下单张 9–45 秒，8 张不可接受 |
| 2 | `plan_slides(topic, 8)` 规划 8 页骨架 | 封面 → 目录 → 第 1..5 部分 → 谢谢 |
| 3 | 背景按页序循环复用，逐页按该页安全区摆文本框 | 页数可以多于底图数，靠 `records[idx % len(records)]` 实现 |

实测：3 张底图 + 8 页排版约 50 秒，产物 200–290 KB。
正文文字是**占位骨架**（`第 1 部分`／`内容页占位：在此填入要点`）——这是刻意的：
生成「看似详实实则瞎编」的正文，对参赛作品是负分。

### 2.3 可行性与成本

| 项 | 实测 |
|---|---|
| 算力 | 单卡 RTX 5070 Laptop 8G；训练 1000 步 22 分钟，推理 28 步 8.5 秒一张（512 出图，再上采样到 1920×1080） |
| 存储 | 基座 3.1 GB + 数据集 330 MB + 适配器 12.5 MB；开源仓库本体 10 MB（不含权重） |
| 数据 | 零采购、零抓取：600 张全部由脚本在本机渲染产出，安全区标注与图像同一次渲染 |
| 时间 | 从零到可演示约 13 天，单人 + AI 编程工具；训练与评测各占 22 分钟与 25 分钟 |
| 依赖 | Python 3.10–3.12 + torch(CUDA)。无显卡或未放权重时自动降级到程序化后端，整条链路照样跑通 |

结论：在赛题「不训练大模型、不购买专用硬件、不做企业级系统」的约束内完成；
全部成本是一台带 8G 显卡的笔记本和约两小时的 GPU 时间。

## 3. 数据集

### 3.1 为什么是合成数据

四条理由，按重要性排序：

- **合规**：不涉及任何第三方图片素材的复制、训练、改编、再分发授权问题。
- **可标注**：安全区是「渲染时就知道」的构造参数，不需要人工标注，也没有标注噪声。
- **可平衡**：6 个预设各 100 张，版式分布可控，避免真实数据的长尾偏置。
- **可复现**：全部由 seed 驱动，同一 seed + 同一版本代码产出逐字节一致的图。

代价必须诚实说明：合成母图的视觉复杂度低于真实照片，模型学到的是这一分布上的先验，
对真实摄影素材的泛化能力未做验证（见第 10 节）。

### 3.2 生成链

1. `data/make_placeholder_assets.py` 程序化生成母图，**8 个家族**（gradient_blobs / geometric /
   paper / stripes / wave / bokeh / fbm_cloud / fbm_silk），每类 36 张；`data/assets_v2` 共 288 张。
2. `make_backgrounds.py`（`GENERATOR_VERSION = "1.5.0"`）合成 1920×1080 背景：
   采样预设 → 影调 → 版式 → 母图几何变换（旋转、镜像、随机窗口裁切、透视 QUAD、径向漩涡、
   偏心光晕、色调分离）→ 影调映射 → 双色调 → 径向光 → 叠色 → 纹理 → 面板/暗角/颗粒 →
   写安全区 `safe_zones` → 生成英文 caption。
3. `validate_dataset.py` 做六项体检；`prepare_dataset.py` 按 `image_sha256` 稳定切分。

### 3.3 体检口径

| 编号 | 查什么 | 阈值 |
|---|---|---|
| C1 | 能否解码、尺寸是否一致 | 必须 |
| C2 | 分布均衡（单类占比、版式分布） | 最大占比 ≤ 0.4 |
| C3 | 安全区局部对比度 | 期望 ≤ 26，告警线 40 |
| C4 | 全局亮度 | 25–236 |
| C5 | 近重复（dHash 8×8，Hamming ≤ 4 且平均色差 ≤ 8） | 重复率 ≤ 5% |
| C6 | 溯源与 caption 自洽 | 必须 |

### 3.4 去重迭代（负结果的完整记录）

| 版本 | 加了什么 | 600 张重复率 |
|---|---|---|
| 1.0.0 | 缩放 + 模糊 + 染色 | 19.7%（118 对） |
| 1.1.0 | + 旋转 / 镜像 / 随机窗口 / 双色调 | 9.83% |
| 1.2.0 | + 透视形变，母图池扩到 216 | 6.33% |
| 1.3.0 | + 径向漩涡 / 偏心光晕 / 色调分离 | ≤5%（40 张抽样 0） |
| 1.3.1 | 修图像质量（不是多样性） | **4.0%（24 对）**，硬问题 0 |

1.3.1 的关键发现值得留档：1.3.0 的 38 对重复里有 31 对是 `clean_white`。原因是那一版把它
模糊到 4.8–32 px 再压成近灰双色调，画面成了「牛奶雾」，不同母图看起来完全一样。
**dHash 撞车只是症状，病是图本身没有结构。**

### 3.5 1.5.0 的三处改动

1. **剔除 36 张 bokeh 母图**（288 → 252）：bokeh 是 12–26 个圆盘叠加，模型学成了
   「在纯色场上点几个圆斑」。第 7 节会说明这个假设最后**被证伪**，但剔除本身仍然正确
   （少一条把毛病再教出去的机会）。
2. **caption 去虚焦语义**：`softly out-of-focus photographic layer` → `even soft photographic tone`。
3. **结构族加模糊下限**：条纹 / 波浪 / fbm 族的 `photo_blur_px` 取 `max(x * 2.2, 18)`。
   踩过的坑：家族名不能用 `asset_id.rsplit("_", 1)[-1]`——`placeholder_287_fbm_silk` 会得到
   `silk`，下限静默失效。

数据集 v4 体检：600 张，**硬问题 0**，软问题 21，近似重复 1.83%，切分 train 548 / val 21。

## 4. 模型与训练

### 4.1 为什么是 LoRA 而不是全量微调

参赛作品要在消费级显卡上可复现。LoRA 只训 1–2 M 参数（全量 860 M），单卡 8 GB 显存可跑，
权重只有十几 MB，可随作品开源。只挂注意力投影层，是因为要学的是「场景语义 → 影调 +
留白版式」的构图先验，不是重学画风。

### 4.2 配置

| 项 | 值 |
|---|---|
| 基座 | Stable Diffusion 1.5（本地目录，离线加载） |
| 分辨率 | 512（出图后再放大到 1920×1080） |
| rank / alpha / dropout | 16 / 16 / 0.05 |
| 目标模块正则 | `.*\.attn[12]\.(to_q|to_k|to_v|to_out\.0)$` |
| 步数 / batch / 梯度累积 | 1000 / 1 / 4 |
| 学习率 / 调度 | 1e-4 / cosine，warmup 50 |
| 精度 | fp16 + 梯度检查点 + sdpa |

### 4.3 实测（RTX 5070 Laptop 8G）

可训练参数 **3,188,736 / 862,709,700 = 0.370%**；首步 17.4 s（CUDA 预热），之后稳定在
**1.25–1.42 s/step**，1000 步约 **21–23 分钟**。

### 4.4 四版权重的迭代（含两次负结果）

| 版本 | 数据 | val_loss @250/500/750/1000 | 结论 |
|---|---|---|---|
| v1 | dataset_v1（中心裁剪） | 0.1163 / 0.0736 / 0.1373 / 0.1124 | 首发权重 |
| v2 | dataset_v1（随机窗口裁剪） | 0.1159 / 0.0731 / 0.1381 / 0.1116 | 无收益，弃用 |
| v3 | dataset_v2（fBm 母图） | 0.1104 / 0.0740 / 0.1205 / 0.0864 | 出图更多结构，但 warm_terra 更花，弃用 |
| v4 | dataset_v3（7 种版式 + 装饰层） | 0.1104 / 0.0740 / 0.1205 / 0.0864 | 出图与 v1 无法区分，弃用 |
| **v5** | dataset_v4（去 bokeh + caption 改口径） | 0.0843 / 0.0558 / 0.0887 / **0.0765** | **当前发布权重** |

v4 的结论是这一节最重要的技术判断：**版式不是模型画的，是合成层用确定性代码画的**。
把数据集的版式从 4 种扩到 7 种、把装饰层叠进训练图，重训后成图与 v1 几乎无法区分——
因为最终观感由后处理决定，模型在 512 上只贡献色场与色调。这条判断直接决定了第 5 节
的设计：想要更多结构，应该改合成层，不是继续加训练步数。

## 5. 学科符号系统

### 5.1 三个学科，三套基准

| 学科 | 底色 | 骨架（必画） | 元素池（每张抽 0–2 件） |
|---|---|---|---|
| 高等数学 | 黑板蓝 #183052 | 坐标纸网格 + 坐标系 + 曲线 1–2 条 + 公式符号 1–3 | 等高线、极坐标网格、矩阵括号、阿基米德螺线、函数值表、傅里叶叠加、级数阶梯、差商三角形、区间阴影（**9 件**） |
| 机械制图 | 蓝晒 #1E487A | 双图框 + 分区刻度 + 标题栏/明细表 + 尺寸链 | 螺纹、粗糙度、节距标尺、键槽剖面、倒角标注、公差带、齿轮轮廓、中心线组（**8 件**） |
| 人生哲学与科学方法论 | 宣纸 #EEE9DE | 稿纸横线（88%）+ 墨弧 1–2 笔 | 一笔圆相、竖排短句、引文框、点阵、印章框、书脊三线、双圆相、飞白墨点、田字格（**9 件**） |

**设计原则一句话**：随机的是「抽到哪些元素、放在哪个空角、多大多密」，
不变的是「每根线都挂在同一套基准上」。

这条原则是被两次反馈逼出来的：第一版元素到处撒，教师反馈「线条凌乱」；
收到只剩图框与标题栏后，又反馈「过于简单」。差别不在数量，在**是否共用一套基准**。

### 5.2 为什么符号必须交给合成层（三组证据）

1. **v4 对照实验**：把数据集的版式与装饰层改掉重训，成图与 v1 无法区分（第 4.4 节）。
2. **底图退平实验**：把模型出图直接拿去叠学科符号，模型自己在画网格与曲线，与叠加的
   符号形成两套线——用户看到的就是「凌乱」。修法是学科预设对底图做**强低通**
   （`GaussianBlur(min(w,h)*0.012)`）并往预设色拉 55%，让底图退回干净纸面。
3. **合成层独立性**：机械制图的所有元素只用到 `ImageDraw` 的线段/矩形/多边形/椭圆，
   与模型完全解耦，因此可以单独调、单独验、单独讲。

### 5.3 干净区保护：两个掩码

- **软掩码** `_zone_mask`：按安全区做羽化衰减，用于网格、曲线、稿纸线这类
  「可以淡淡透进压字区」的元素。
- **硬掩码** `_zone_mask_solid`：**不羽化**，用于剖面块、公式符号、印章这类
  「有边界的小图形」——它们一旦落进压字区就是一块明显的对比度。

踩过的坑：软掩码的羽化半径按 `min(w,h)*0.03` 算约 32 px，比页脚/图注那类 54–65 px 的
窄条还高，掩码中心降不到 0，装饰线照样穿过去。所以窄条必须用硬掩码。

另有一处必须注意：**图框、标题栏、尺寸线不参与掩码**。它们是 2–3 px 的细线，局部对比度
贡献可以忽略；而被掩码挖掉一角之后，线会断成几截——这正是上一版「底部散着几截孤立的线」
的成因。这条不是审美，是 bug。

### 5.4 版式

学科预设只用三种版式（`vignette_plain` / `center_band` / `top_band`），且**不画磨砂面板卡片**。
原因是教师的第一条意见：高数的板书内容会被磨砂色块遮挡。学科背景需要的是整片可用的纸面，
不是「左面板 + 右文字」的双栏构图。

### 5.5 元素池的第二次扩容：为什么全部不带箭头

第一轮元素池每科只有 4–5 件，用户连着生成几张就会看出重复（组合空间只有几十种）。
第二轮把池子扩到 **高数 9 / 机械 8 / 哲学 9**，同时**把所有「指向空处」的箭头清掉**。

清掉的四类（每条都是用户看出来的，不是我们自查出来的）：

| 原元素 | 问题 | 改法 |
|---|---|---|
| 高数「向量箭头」6–11 根 | 方向随机、不指向任何对象，读起来就是「乱画的箭头」 | 整件删除，换成**极坐标网格**（同心圆 + 等角度径向刻度） |
| 机械「引出线」 | 指向画面空白处 | 只在画了局部放大圈时才出现，起点在圆周上、箭头落在圆周上 |
| 机械「基准符号」「局部放大标记」 | 都带箭头且指向空处 | 从池子里撤掉 |
| 机械「粗糙度」的右侧长尾 | 尾部在制图里是写 Ra 值的位置，画面里没有数值就只剩一根箭杆 | 只留「√ + 顶点」，缩到 0.2s 见方 |

**保留的箭头只有两类**：坐标轴末端、尺寸线两端。它们在数学与制图上是有语义的
（表示方向与量度边界），删掉反而不成立。

新增的 12 件全部是「自洽图形」：傅里叶叠加、级数阶梯、差商三角形、区间阴影、
倒角标注、公差带、齿轮轮廓、中心线组、书脊三线、双圆相、飞白墨点、田字格。

元素密度做成三档：**精简 0 件 / 标准 1 件 / 丰富 2 件**（motif_richness）。
组合空间因此变成 C(9,2)=36、C(8,2)=28、C(9,2)=36，再叠加位置/尺寸的连续随机，
同 seed 之外肉眼已看不出重复。

代价必须写清楚：元素变多后，压字区的最差对比度从 5.6 升到 **20.5**（阈值 26）。
原因是元素靠边抽样时会擦到安全区边缘。仍在阈值内，但余量从「很宽」变成「够用」。
可行的收敛手段（尚未实施）：把候选位置从 24 个提到 40 个、并要求离安全区外扩 1.5%
以上；或抽样命中安全区边缘时换一件。

### 5.6 符号质感：让模型出手感、代码出几何

「学科符号是矢量画的，看着太干净」是第三版最想做的一件事。直接把符号交给模型
训不出来（第 5.2 节三组证据），所以走中间路线：**模型只提供纹理，几何仍由代码画**。

四步：

1. **取纹理**：用发布权重生成 4 张 512×512 的「平铺材质」（纸、黑板、蓝晒、象牙纸），
   提示词里明确 lat ... no objects, no text。
2. **只留高频**：hi = g - GaussianBlur(g, 18)，再拉均衡化。大尺度亮度差是模型的构图，
   不是纸纹；不做这一步，贴上去等于把模型画的明暗又糊回画面。实测高频 std：
   paper **18.86** / chalk **10.22** / blueprint **23.57** / ivory **25.90**。
3. **按学科绑材质**：高数→黑板、机械→蓝晒、哲学→纸。
4. **只乘在「新画上去的那一层」上**：`after = before + (after - before) * grain，
   几何一个像素都不动，只有线条内部的墨色不匀。

三个必须的工程约束：

- **1:1 平铺而不是放大**。早期版本把 512 的 tile 放大 3.75 倍铺满画面，颗粒变成 4 px，
  把 2–3 px 宽的制图线压成断续——语义上等于把轮廓线画成了虚线。改成按块 1:1 平铺 +
  奇偶块镜像翻转后，颗粒尺度与线宽同量级，不再破坏线。
- **粒度的下界必须 > 0.8**。归一化后 clip(0.82, 1.30)：往下最多压 18%。低于这个值时，
  一条 2 px 的线在某些行会被压到接近背景，1:1 看就是断口。
- **只加不减**：纹理允许把某段线「画浅」，不允许「画没」。这是「墨色不匀」与「虚线」的分界。

一次差点误判的记录：把成图 2× 放大看，制图线看起来断成虚线，连续三轮调参都没修好。
最后改用数值判定——沿外框竖线统计每行峰值亮度（`a[100:900, 56:76].max(axis=1)）：

| | 均值 | 标准差 | **最小峰值** |
|---|---|---|---|
| 纯矢量 | 58.4 | 8.66 | **54.0** |
| 模型笔触 | 58.5 | 10.06 | **54.0** |

最小峰值完全相同，说明线根本没有断——「虚线」是 2× NEAREST 放大叠加 JPEG 压缩
造成的视觉假象。这条记录留在报告里，是因为它说明了一件事：**判断「有没有变差」
要用可复算的量，而不是截图。**

质感选项暴露为 symbol_style = vector | brush，默认 ector（保守）；
笔画选项与六个可调项的关系见第 8.5 节。

## 6. 评测

### 6.1 设计

固定 40 条中文需求（`eval/prompts_v1.jsonl`，覆盖学术/商务/人文/环保/科技/水墨六类场景），
同一 seed 基线，五个后端跑同一条 `SDService` 流水线：

| 后端 | 是什么 | 在评测里的角色 |
|---|---|---|
| `lora` | 本作品 | 待评估对象 |
| `sd_base` | 同流水线，不加载 LoRA | 消融：LoRA 到底带来了什么 |
| `procedural` | 把数据合成算法直接当生成器 | 消融：证明「训了模型」比「套模板」强在哪 |
| `procedural_raw` | 同一个入口，只是 `with_panel=False` | 消融：预设 + 版式 + 安全区约束究竟值多少 |
| `noise` | 随机低对比噪声 | 下界：证明指标本身有区分度 |

### 6.2 结果（40 条 × 5 后端 = 200 张）

| 指标 | 方向 | lora | sd_base | procedural | procedural_raw | noise |
|---|---|---|---|---|---|---|
| `safe_zone_std` | 越低越好 | **6.428** | 16.047 | 13.131 | 13.945 | 14.717 |
| `artifact_hf` | 越低越好 | 6.234 | 13.396 | **4.670** | 5.244 | 128.943 |
| `relevance` | 越高越好 | 0.789 | 0.748 | **0.849** | 0.637 | 0.552 |
| `layout_ok` | 越高越好 | **1.000** | 0.750 | 0.950 | 0.000 | 0.000 |
| `seconds`（单张） | 越低越好 | 8.520 | 7.539 | **0.911** | 0.907 | 0.186 |

达标率（`std ≤ 26`）/ 版式合规率：`lora` **100% / 100%**，`sd_base` 77.5% / 75.0%，
`procedural` 92.5% / 95.0%，`procedural_raw` 95.0% / 0%，`noise` 100% / 0%。

### 6.3 三条可核验的结论

1. **LoRA 的贡献是可测的，而且不是「结构后处理」的功劳。** `lora` 与 `sd_base` 走的是
   同一份代码、同一个结构层、同一个 seed，唯一差别是加载不加载适配器。结果安全区对比度
   6.43 对 16.05（2.5 倍）、版式合规 100% 对 75%。如果合规模板起决定作用，`sd_base` 应该
   同样接近 100%——它没有，40 条里有 10 条把安全区对比度推到 24.8–28.9。
2. **单看 `safe_zone_std` 会被平凡解骗。** `noise` 后端的达标率也是 100%，但它版式合规 0%、
   高频伪影 128.9——它「干净」是因为什么都没画。这提醒必须和 `artifact_hf` + `layout_ok` 联读。
3. **模型并非全面获胜，照实写。** `procedural` 在 `artifact_hf`（4.67 对 6.23）、
   `relevance`（0.849 对 0.789）、耗时（0.91 s 对 8.52 s，快 9.4 倍）三项更好。
   规则渲染的画更干净、色调更贴合预设、且没有推理成本；它输在多样性（同一预设出图几乎同质）
   与需要 GPU——这两点恰好是本作品存在的理由。

### 6.4 指标口径的一次修正（记录在案）

`layout_ok` 及其背后的 `layout_compliance()` 改过两次口径：

| 版本 | 判据 | 实测结果 | 为什么错 |
|---|---|---|---|
| v1 | 左半图 vs 右半图的平均梯度 | 版式完全正确也只有约 1/3 通过 | 面板只占宽度 30–40%，差异被稀释 |
| v2 | 面板矩形 vs 剩余区域的平均梯度 | `procedural` 只有 0.500 | 量的是「母图纹理有多强」，与版式无关 |
| v3 | 标题区/正文区的局部对比度 ≤ 26 | `procedural` 0.917，`noise` 0 | 直接对应「放字的地方够不够干净」 |

v2 的具体反例（14 张样本的梯度读数）：`clean_white` 的母图本身就是大面积白底渐变，
留白侧 `mean_grad 0.411`、面板侧 `0.588`——母图本来就没有纹理，此时「哪边更干净」
不是一个有意义的量；面板反倒因为边缘那道刻意做出的淡过渡带而梯度更高，于是版式正确却被判
不合规。而纹理强的 `warm_terra` 上比值是 0.28，轻轻通过。一个指标如果在母图纹理强时通过、
纹理弱时失败，那它量的是母图，不是版式。v3 改成绝对判据后这个耦合就断掉了。

## 7. 圆斑溯源：一次被证伪的假设

用户在网页上发现成图中央有一块圆形色斑。这一节记录它从「猜」到「证」再到「修对地方」的全过程，
因为结论与我们最初的判断相反。

**第一步：先确认斑点在不在模型里。** 用同一个 seed 直接调 `_gen_diffusers`，绕过整个合成层
出图——斑点照样在。所以它不是后处理画上去的。

**第二步：斑点的形状从哪来。** 训练集原有一族 bokeh 母图（12–26 个圆盘径向叠加），
caption 里写着 `softly out-of-focus photographic layer`。看起来像是模型把这条规则学成了
「在纯色场上点几个直径 30–60 px 的圆」。据此做了一个 v5（`configs/lora_v5.yaml`）：
剔除 36 张 bokeh 母图、改 caption、给结构族加模糊下限、重新生成 600 张、重训 1000 步。

**第三步：假设被证伪。** 同一个 seed 下，v1 与 v5 的原始出图里，圆斑出现在**完全相同的
位置**。两版权重不同、训练数据不同，位置却一样——说明它来自基座模型在这个 seed 下的隐变量
结构，不是这 600 张图教出来的。**「去掉 bokeh 就能消斑」这个判断是错的**，v5 并没有消掉它。

**第四步：把基座侧的可能性逐条试完。**

| 试过的手段 | 结果 |
|---|---|
| 换调度器（DPM-Solver / DDIM / EulerAncestral / Heun） | 斑点仍在，且落在同一位置 |
| 降低 CFG（7.5 → 4.5 → 3.0） | 位置不变，反差小一些 |
| 初始 latent 高通（减去大尺度模糊后反标准化） | 斑点仍在原位；σ=3.0 还会在边角引入新的圈状伪影 |

三样都换不掉，唯一不变的是它在图像坐标系里的位置。所以它既不是采样过程长出来的，
也不是初始噪声的问题，而是基座 UNet / VAE 在特定空间位置上的固有伪影，
被 LoRA 产出的均匀色场「显影」了出来。成像前没有干净的拦法（除非换基座或换分辨率，
两者都超出本作品的约束）。

**第五步：修在能生效的地方——合成层。** 两处，都在 `_compose_diffusers` 里：

- `suppress_blotches(strength=0.55)`：全图带阻，直接减掉 20–90 px 尺度的亮度起伏，
  压掉斑点的低频「体量」，保留更细的颗粒与更大的整体渐变。
- `despeckle_discs(k_sigma=4.0, sigma_mid=46.0, dilate=16.0)`：中频带取孤立极值 → 掩码 →
  **只在掩码内**减掉那一层。

第二条走一次弯路值得记：最初用「换成大模糊」填空，斑点没了，但掩码范围里连颗粒一起消失，
1920 下变成一块过分光滑的圆片，比原斑点更显眼。改成「只减中频、保留颗粒」才对。
实测斑点区与干净区的平均亮度落差 **8.6 级 → 2.0 级**。

**第六步：试过「检测到就重抽」，放弃了。** 既然压不住就重画一张，前提是能可靠判断
「这张有斑点」。标定了三种指标（中频极值比、22 px 圆盘匹配滤波、去斑掩码占比）：
已知有斑点的两张得分 11.50 / 11.00，其余 20 张落在 1.47–19.00——**完全重叠**，
而且最高分落在肉眼干净的 `clean_white` 图上（大面积亮底会放大微小起伏）。

更进一步，连「按分数挑最好的一张」也不成立：同一请求内连出 6 张按分数排序，
分数最低（2.37）的那张是**顶部一大块明显亮斑、六张里最丑**的——因为这个分数只度量
20–90 px 中频对比，大而平滑的斑块落在低频被带阻压掉。按它做 best-of-N 会系统性地选错。

于是改成**人挑 + 按槽位重画**：界面保留 1/2/4 张可选，每张旁边一个「重画这一张」按钮，
换 seed 只重画那一个槽位、原地替换记录（保证屏幕上的图和导出的 pptx 是同一份）。

**为什么最后还是把发布权重换成了 v5。** 消斑不靠它，但它有三处更干净：训练集里不再有
「虚焦光斑」这条 caption（少一个把毛病再教出去的机会）、7 种版式 + 装饰层的数据、
`val_loss` 也低一档。代价是 v5 出图明显更灰，原来的 12% 叠色拉不回预设色，
所以色调合成改成按偏离预设色的程度动态补偿。

| 压字可读性 | 靠肉眼试错，返工是常态 | 安全区对比度 6.428（阈值 26），达标率 100% | 返工从必然变成偶发 |
| 教学批量场景 | 一位教师 10 个课件 × 20 页，手工不可能 | 200 张背景约 28 分钟机器时间 | 从「做不起」到「顺手做」 |

可复用价值（对应评分表「开放成果与复用价值」）：数据集生成器、安全区约束层与五后端评测脚本
都以 MIT 开源，任何需要「留白 + 可压字」的场景（课件、海报、封面、视频底图）可以直接复用同一套
指标与脚本，而不只是复用图片。

不能量化的部分照实说：审美偏好没有测——人工盲评（同一批背景压上真实文字、请人打分）还没做，
见第 10 节第 7 条。

## 9. 合规与开源

| 产出 | 许可证 | 说明 |
|---|---|---|
| 源代码（`app/` `data/` `train/` `eval/` `tools/`） | MIT | 仓根 `LICENSE` |
| 数据集（600 张 + 母图 + 标注 JSONL） | CC BY 4.0 | 署名「pptbg 团队」 |
| LoRA 适配器权重 | CreativeML OpenRAIL-M | 是 SD 1.5 的衍生作品，必须沿用基座条款 |

- **训练数据不来自任何第三方图片库**，也不涉及 CC0 数据集；全部由脚本渲染，母图同样是程序生成。
  这条选择是从源头消除「公开可访问是否等于可训练」的合规判断。
- 基座权重随作品不重分发，只分发自己训的适配器；基座的许可证全文与来源记录在
  `tools/hf/stable-diffusion-v1-5/README.md` 与 `artifacts/model_manifest.json`。
- 下载依赖时使用了 `hf-mirror.com` 镜像，已在清单中如实披露。
- 开发中遇到一个第三方库的真实缺陷，已向上游反馈：[huggingface/peft#4067](https://github.com/huggingface/peft/issues/4067)（2026-10-28 提交，状态 open）。报的是 `NoMatchingPeftModuleError` 的提示没有说明 `target_modules` 由 `re.fullmatch` 匹配**完整点分路径**，导致短名（如 `attn.to_q`）永远匹配不上、用户也无从得知正确写法。
  这是**体验改进类 Issue，不是代码 PR**，也不主张已被采纳；本作品对开源的贡献主体仍是「MIT 代码 + CC BY 4.0 数据集 + OpenRAIL-M 适配器」，该 Issue 仅作工程参与度的佐证。

## 10. 限制（诚实清单）

1. **合成数据的先验**：母图是程序化纹理，视觉复杂度低于真实摄影。模型学到的是这一分布上的
   构图先验，对真实素材的泛化能力未验证。
2. **学科符号是规则而非学习**：第 5 节已证明符号由合成层绘制。这意味着「模型的智能」
   体现在色场与留白，不体现在「认识数学」。综述里不能把它说成模型学会了学科。
3. **`relevance` 口径偏向规则渲染**：其构成是 0.5×关键词命中 + 0.3×色调命中 + 0.2×版式合规，
   `procedural` 用同一套 tint 渲染，天然占优。这一项不能用来论证「模型优于规则」。
4. **单张 8.5 秒**（RTX 5070 Laptop，28 步），比规则慢 9.4 倍；降到 20 步的画质损失未量化。
5. **整套 PPT 的正文是占位骨架**，不生成实质性内容——这是刻意的取舍。
6. **限功率会显著拖慢**：本机测得 `enforced.power.limit` 曾被限制到 50–55 W（正常 100–140 W），
   此时单张从 8.5 秒退化到 100 秒以上。演示前必须插电源并把电源模式设为「最佳性能」。
7. **未做人工盲评**：当前所有指标都是脚本指标，真正该做的对照是「同一批背景，压上真实文字，
   请人打分」。这件事没做，报告里也不假装做过。


8. **元素密度拉到「丰富」后安全区余量变窄**：压字区最差对比度 20.5（阈值 26），
   比「标准」档的 5.6 高很多。成因是元素靠边抽样时偶尔擦到安全区边缘，
   不是元素本身太亮。收敛手段（候选位置 24→40、离安全区外扩 1.5%、命中边缘就换一件）
   尚未实施，因此「丰富」档默认不开启。

9. **模型笔触只在 2–3 px 细线上验证过**。它乘的是「新画上去那一层」的透明度，
   对 40 px 以上的粗形状（剖面块、区间阴影）效果尚未单独评估；
   当前所有学科元素都在 1–4 px 线宽区间，因此这条限制暂时不影响出图。
## 11. 复现

```bat
:: 1) 母图与清单
pptbg data\make_placeholder_assets.py --out data\assets_v2\raw --per-kind 36 --size 1600 --seed 7
pptbg data\asset_manifest.py scan --raw data\assets_v2\raw --out data\assets_v2\manifest.jsonl

:: 2) 数据集（600 张，生成器 1.5.0）
pptbg data\make_backgrounds.py --assets data\assets_v3\manifest.jsonl ^
      --assets-root data\assets_v2\raw --out data\dataset_v4 --count 600 --seed 20261016

:: 3) 体检与切分
pptbg data\validate_dataset.py --records data\dataset_v4\records.jsonl ^
      --images-root data\dataset_v4\images --out data\dataset_v4\report
pptbg train\prepare_dataset.py --records data\dataset_v4\records.jsonl --out data\splits_v4

:: 4) 训练（约 22 分钟）
pptbg train\train_lora.py --config configs\lora_v5.yaml

:: 5) 评测（40 条 × 5 后端）
pptbg eval\run_eval.py --prompts eval\prompts_v1.jsonl --out eval\results_v1

:: 6) 网页与端到端
pptbg app\server.py --port 8763
pptbg app\smoke_test.py
```

## 12. AI 生成内容与工具使用声明

1. **作品本身的 AI 成分**：输出的背景图由模型生成（SD 1.5 + 自研 LoRA）；
   训练数据由确定性程序合成，不是模型生成。输出图像属于 AI 生成内容，
   不主张其作为「团队自主知识产权」；团队主张的是代码、数据集、训练配置与评测方法。
2. **开发过程使用的 AI 辅助工具**：开发过程使用了大型语言模型编程工具协助编写代码与文档。
   团队对所有提交内容负责：每一个脚本的输入输出、每一个数字都可以按第 11 节重跑复核，
   关键结论（数据集体检、评测指标、圆斑溯源）均由仓库脚本产出，而不是工具描述。
3. **未使用 AI 生成任何参赛身份的证明材料。**

## 13. 总结与展望

### 13.1 项目总结

**完成情况。** 交付了一件能跑、能验、能复现的作品：600 张带安全区标注的合成数据集（母图 288 张、
8 个纹理家族，近似重复 1.83%，硬问题 0）；一个 0.370% 可训练参数的 LoRA（1000 步、22 分钟、
单卡 8G 可复现）；五个后端的对照评测（40 条需求 × 5 = 200 张，LoRA 的安全区对比度 6.428，
同流水线去 LoRA 为 16.047）；网页端到端 7/7 通过、可一次导出 8 页可改字的 .pptx；
代码、数据集与复现命令开源在 GitHub，并向上游提交了一条有完整复现步骤的 Issue（peft #4067）。

**主要价值。** 把「这张背景图能不能压字」从一个只能凭手感判断的事，变成了可度量
（局部亮度标准差 ≤ 26）、可训练（安全区坐标与图像在同一次渲染中产生，无标注成本）、
可核验（同 seed、同流水线、只换后端）的工程问题；并把这套生成器、约束层与评测脚本开放出去，
别人可以用同一套指标评价自己的背景图，而不是只凭主观。

**团队收获。** 三条最实在的：① 把一个模糊需求拆成能写进脚本的指标，比写更多功能难；
② 学会用负结果判断假设真假——第 7 节那条「圆斑是不是训练数据带出来的」被 1000 步的重训否掉了，
省下的是后面所有基于错误归因的改动；③ 知道许可证义务要一路追溯到基座（第 9 节），
「公开可访问」不等于「可以随便训练和再分发」。

**未完成事项（照实写）。** 演示视频尚未录制；人工盲评（同一批背景压上真实文字、请人打分）未做；
随机裁剪版权重没有重训，所以第 4 节的对照结论仍带一条待验证的尾巴；
数据集的「丰富档」抽样会蹭到安全区边缘，余量从 5.6 掉到 20.5，收敛手段只有方案、尚未实现；
报名缴费与正式提交尚未完成。

### 13.2 后续计划

1. **功能优化。** 把元素池的抽样从「随机取位置」换成「拒绝采样」：候选位置与安全区外扩 1.5% 相交就换一个，
   让「丰富档」的元素密度不再以压缩安全区为代价；同时把安全区对比度的目标值做成可调参数，
   向需要更高对比度的场景开放。
2. **测试扩展。** 补两项现在缺的：一是人工盲评，固定 20 组需求、每组 4 张，请非团队成员排序；
   二是弱显存复现（6G 卡、步数降到 20），把「降到 20 步画质损失多少」量出来，而不是继续用「未量化」交代。
3. **开放维护。** 仓库按语义化版本发版，每个版本附一条一行可跑的复现命令；补 Issue 模板与贡献指南；
   把 peft #4067 的结论写进 README 的常见问题，后来的人不用再踩一次。
4. **社区协作。** 若上游合并或给出更优写法，跟进更新本仓库的 	arget_modules 正则；
   数据集生成器拆成独立包，让别的赛题（需要「留白 + 可压字」的场景）能直接复用。
5. **应用推广。** 先在小范围真实场景试：请 3 位以上任课教师用本工具出自己的课件背景，
   收集「哪些预设被反复选中」「哪些背景压字后仍然糊」两类反馈，再决定下一版优先改配色还是改版式。
   商业化不是本作品的必选项，暂不规划。
